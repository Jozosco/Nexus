## 1. Feature Mart (피처 마트)

### 왜 필요한가
우리는 20여 개 소스에서 **주기가 제각각인** 데이터를 받는다 — CBOT 종가는 일별,
WASDE는 월별, PSD는 연별, 관세청은 월별(익월 15일경 공표), GAIN은 비정기.
모델은 "2026년 8월 19일에 알 수 있었던 모든 변수의 값"을 **한 줄**로 받아야 학습이 되는데,
원본 상태로는 각 파일에 흩어져 있어 그 한 줄을 만들 수 없다.

### 무엇인가
**거래일 × 지표**의 격자 테이블이다. 세로축은 거래일(2010-01-04 ~ 2025-12-31 = 4,023일),
가로축은 지표(6,002열). 각 칸에는 **그날 시점에 알 수 있었던 가장 최신값**이 채워진다.

| 구분 | 원본(raw) | Feature Mart(gold) |
|---|---|---|
| 형태 | 소스별 파일, 롱포맷(날짜·지표·값) | 단일 테이블, 와이드(날짜 × 지표) |
| 주기 | 제각각 | 거래일로 통일 |
| 값의 의미 | "이 지표가 이 시점에 관측됨" | "이 날짜에 **알 수 있었던** 값" |
| 용도 | 보관·검증 | **모델 입력** |

부가 장치 3종:
- `age_` 컬럼 — 그 값이 며칠 전 것인지 함께 기록(이월값인지 신규 발표인지 구분)
- 신선도 상한 — 주기×4+15일(최대 800일) 초과하면 결측 처리(죽은 값이 살아있는 척 방지)
- `target_` 접두 — 목표변수(CBOT_BO_CLOSE)를 피처와 물리적으로 분리

### 어느 단계에서 쓰나
```
수집(커넥터) → 품질검증(C-08) → EDA(C-06) → 준비도 게이트 → 【Feature Mart 조립】 → G1/G2/G3 분석
```
파이프라인의 **마지막 전처리 단계**이자 **모든 모델의 유일한 입력 관문**이다.

### 없으면 무슨 일이 생기나 — 실측 사례
Mart를 만들면서 **값충돌 48,789건**이 검출됐다. 예컨대 NASS 대두 생산량이
`SOYBEAN_PROD_BU` 코드 하나에 아이오와주·아칸소주·전국 합계가 뒤섞여 있었다.
Mart 없이 바로 모델에 넣었다면 **"미국 대두 생산량"이라는 변수가 매 실행 다른 주의 값을
가리키며** 학습됐을 것이다. Mart의 하드 게이트가 이를 차단해 축 분리(주·국가·지역·
생산방식)를 강제했고, 그 결과 지표가 484종 → **1,463종**으로 정밀해졌다.

## 2. as-of (시점 정합성)

### 왜 필요한가
8월 WASDE 보고서는 **8월 12일에 발표**된다. 그런데 그 데이터의 "대상 기간"은 8월이다.
이걸 그냥 "8월 1일 데이터"로 쓰면, 모델은 8월 1일에 **아직 세상에 없던 정보**로
8월 5일 가격을 맞히게 된다 — 시험 문제를 답안지 보고 푸는 셈이다(**미래 정보 누수**).
백테스트 성능은 화려해지지만 실전에서는 재현되지 않는다.

### 무엇인가
모든 관측치에 **5개의 시각 필드**를 붙여 "언제 일어났나"와 "언제 알 수 있었나"를
분리하는 규약이다.

| 필드 | 의미 | 예 (WASDE 8월호 STU) |
|---|---|---|
| `event_time` | 사건·대상 시점 | 2026-08-01 |
| `period_end` | 대상 기간 종료 | 2026-08-31 |
| `release_time` | **실제 발표일** | 2026-08-12 |
| `available_at` | **우리가 쓸 수 있게 된 시각** | 2026-08-12 |
| `source_vintage` | 개정본 식별자 | 2026-08 회차 |

**핵심 규칙 한 줄**: `모델의 t일 입력 = available_at ≤ t 인 가장 최근 값`

### 어느 단계에서 쓰나
- **수집 시점**: 커넥터가 저장 직전 `attach_asof()`로 5필드를 부여(규칙은 한 파일에서 단일 관리)
- **게이트**: `validate_asof.py`가 필드 누락·시간 역전·미래값을 검사, 위반 시 모델 진입 차단
- **Mart 조립**: ASOF JOIN이 이 필드를 기준으로 "그날의 값"을 선택
- **분석**: G1/G2가 이 규약을 전제로 학습·검증

### 없으면 무슨 일이 생기나 — 실측 사례
1. **FRED 실측 게시일**: 발표일을 추정하지 않고 FRED가 제공하는 실제 게시일을 받아쓴다.
   실측 7/11이 추정 7/16보다 5일 빨랐다 — 추정했다면 5일치 정보를 못 쓸 뻔했다.
2. **VIX 1일 지연**: CBOT 대두유 마감은 14:20 ET, VIX 확정은 16:15 ET. 같은 날짜로 붙이면
   "t일 종가 예측에 t일 종가보다 늦게 정해진 값"을 쓰게 된다. 날짜만 보는 검사로는
   안 걸려서 **장중 확정 시각** 판정표를 따로 뒀다.
3. **13차 런**: as-of 게이트가 관세청 데이터의 시각 필드 전량 결측을 잡아내 모델 진입을
   차단했다. 게이트가 없었으면 시점 미상 데이터가 조용히 학습됐을 것이다.

## 3. DuckDB

### 왜 도입했나 (선택 이유)
Mart 조립의 핵심 연산은 **ASOF JOIN**이다 — "각 거래일마다, 그 시점 이전의 가장 가까운
관측치를 붙여라". 4,023일 × 1,400여 지표 = 약 580만 조합을 이 규칙으로 정렬해야 한다.

| 방식 | 문제 |
|---|---|
| pandas만 사용 | 지표마다 반복 루프 — 느리고, ASOF 로직을 직접 구현하다 실수하기 쉬움 |
| Snowflake 등 서버 DB | 서버·계정·네트워크 필요. 사내 방화벽 안에서 CI가 못 붙음 |
| **DuckDB** | **ASOF JOIN이 SQL 문법으로 내장**, 서버 불필요(파일·메모리에서 실행), parquet 직접 질의 |

### 무엇인가
"분석용 SQLite"에 해당하는 **임베디드 분석 DB**다. 설치는 `pip install duckdb` 한 줄,
서버 프로세스가 없고, parquet 파일을 그대로 SQL로 조회한다. 무료 오픈소스.

### 어느 단계에서 쓰나
**Feature Mart 조립 단계에서만** 쓴다(`build_feature_mart.py`). 수집·저장은 parquet,
분석은 pandas·scikit-learn이 담당하고, DuckDB는 "시점 정합 격자를 만드는 연산 엔진"
역할에 국한된다.

### 도입 시 함께 고려한 것
- **이식성**: 데이터가 parquet에 그대로 남아 DuckDB를 걷어내도 자산 손실이 없다.
  11월 사내 통합(Snowflake) 때 이관 비용이 최소가 되도록 의도적으로 선택했다.
- **교차 검증**: DuckDB 결과를 pandas로 **독립 재계산**해 대조한다. 엔진 하나를 맹신하지
  않기 위한 장치이며, 현재까지 불일치 0건.
- **대안 기각**: Supabase(외부 PostgreSQL)는 회사가 폐지 중인 기술을 사외에 신설하는
  역행이라 도입을 철회했다.

## 4. 세 개념의 관계 (한눈에)

```
[수집]  각 소스 → parquet(롱포맷)
           │
           ├─ as-of 5필드 부여 ················ "언제 알 수 있었나"를 기록
           ▼
[검증]  C-08 품질 게이트 · as-of 게이트 ······· 위반 시 모델 진입 차단
           ▼
[조립]  DuckDB ASOF JOIN ····················· 연산 엔진
           ▼
      Feature Mart (4,023일 × 6,002열) ········ 모델의 유일한 입력
           ▼
[분석]  G1 변수중요도 / G2 가격밴드 / G3 레짐
```

세 가지는 별개 기술이 아니라 **하나의 목적**을 위한 3단 구성이다:
**"과거 어느 시점으로 돌아가도, 그날 실제로 알 수 있었던 정보만으로 판단을 재현할 수
있게 만든다."** 이것이 차별화 브레인스토밍에서 3개 관점이 동시에 지목한
'as-of 타임머신'의 기술적 토대이기도 하다.

## 5. ABCD 등 곡물 메이저 거래구조 조사 — 워크플로우·출처 (문의 답변)

### 조사 경로 4단
| 단계 | 방법 | 이번 조사에서의 실제 사용 |
|---|---|---|
| ① 자체 코퍼스 | 저장소에 확보된 원문 PDF를 판독 | USDA FAS GAIN 2,090건·FAO AMIS 137건 중 한국 관련 보고서 2건 전문 판독(2024-03 Vegetable Oil Market Overview 39,616자 · 2026-03 Oilseeds Annual 53,827자) |
| ② 실측 데이터 역산 | 관세청 GW 수입통계로 채널 구조를 계산 | 원산지별 화물 크기·주기·CIF 분포 산출(AR 45개월 준연속 중앙 10,981MT/CIF 1,183 vs US 12개월 간헐 중앙 15,115MT/CIF 1,383) |
| ③ 공개 웹 조사 | 업계 표준·기업 공시·전문지 | FOSFA 계약(세계 유지 거래 85%)·S&P Global basis 호가 사례·ADM/LDC 증설 발표·Wilmar 연혁 |
| ④ 교차검증 | GPT-5.6-Sol(xhigh) 상시 검증 | 문서 push 시 자동 발화 — 이번 문서는 "지적 사항 없음" 판정 |

### 출처 등급 구분 (문서에 항상 명시)
- **실측**: 우리 파이프라인이 수집·계산한 값 (관세청 CIF, GATS 물량) — 최상위 신뢰
- **공개**: 공식 보고서·기업 공시·업계 표준 문서에 명시된 사실
- **추정**: 위 둘로부터 추론한 해석 — 반드시 근거와 함께 "추정"으로 표기

### 구조적 한계 (조사로 메울 수 없는 것)
- **기업별 수입 분해 불가**: 관세청은 국가별만 공표한다. "어느 정제사가 어느 트레이더에게서
  샀는가"는 공개 데이터에 존재하지 않는다.
- **실측 basis 호가 부재**: 현재는 관세청 CIF 역산(월별·후행)으로 근사한다. 일별·선행
  호가는 Platts/Fastmarkets 구독이 필요하다(결정 대기 DQ-1).
- **화물 단위 추적 부재**: 선박별 선적 시점은 Kpler/Vortexa 유료 구독 영역이다.
