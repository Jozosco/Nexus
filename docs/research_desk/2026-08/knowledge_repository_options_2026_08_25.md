## 2. 권장안 — Knowledge Mart (기존 자산 위에 얹는 지식 인덱스)

**한 줄 정의**: Feature Mart가 "수치의 시점 정합 격자"이듯, Knowledge Mart는
"**문서·결정·용어의 단일 질의 격자**"다 — 같은 기술(DuckDB+parquet), 같은 원칙(이식성).

### 구조

```
[정규화] 요약 md 2,175 + MEMORY 결정 300+ + research_desk 66 + 시맨틱 용어 152
             ↓  (문서id · 유형 · 날짜 · 태그 · 엔티티 · 본문 · 출처경로)
[저장]   data/gold/knowledge_mart.parquet  ← 단일 파일, git/Blob 어디든 승계
             ↓
[질의]   scripts/knowledge_search.py "아르헨티나 수출세 인하 근거"
             ↓  DuckDB(메타 필터) + TF-IDF(scikit-learn — 승인됨) 랭킹
[응답]   상위 N건: 문서 경로 · 발췌 · 날짜 · 근거 등급 — EvidenceSpan 계약 준수
```

### 왜 이것인가 (근거 5)

1. **결정 재사용**: R-012 "DuckDB(ASOF JOIN) 우선" · D-025 "DuckDB 유지 — 이식성
   100%·parquet 전량 승계"가 이미 내려진 결정. 신규 인프라 심의가 **불필요**하다.
2. **자산 재사용**: 인덱스 CSV 11열이 메타데이터 필터 축을 무상 제공, 시맨틱 레이어의
   152 용어·signal_tag_mapping이 질의 확장(용어→동의어→문서)을 무상 제공.
3. **근거 규율 내장**: NotebookLM의 핵심 가치인 "인용 각주"가 우리는 이미
   **provenance.yaml EvidenceSpan**(page·원문 인용 100% 일치 강제)으로 성문화돼
   있다 — 새로 설계할 것이 없고 준수만 하면 된다.
4. **비용 0·승인 범위 내**: duckdb·scikit-learn 전부 승인 라이브러리, 서버·계정·
   구독 없음. 11월 이관 시 parquet 그대로 Blob/Snowflake 승계(잔존자산 100%).
5. **인수인계 내성**: 단일 parquet + 단일 CLI — 사람이 바뀌어도 `knowledge_search.py
   "질문"` 한 줄이면 5개월치 축적이 검색된다.

### 로드맵

| Phase | 내용 | 조건 | 소요 |
|---|---|---|---|
| **1** | 카탈로그 빌더 + TF-IDF 검색 CLI + 에이전트 공용 진입점 | 조정자 승인만 | ~반나절 |
| **2** | 의미(임베딩) 검색 — sentence-transformers(승인됨), 임베딩은 parquet 컬럼로 저장(벡터DB 불요) | **HF egress 2종**(8/29 신청서 v2.1에 추가 완료) 승인 후 | ~반나절 |
| **3** | Azure AI Search 재평가(관리형 전환 여부) | 11월 이관 후 | 별도 |

### 한계(정직하게)

- TF-IDF(Phase 1)는 키워드 기반 — 동의어·개념 질의는 시맨틱 용어 확장으로 보완하나
  임베딩(Phase 2)보다 약함. Phase 1→2는 같은 스키마라 재작업 없음.
- 생성형 응답(문서 종합 서술)은 저장소가 아니라 **에이전트의 몫** — Knowledge Mart는
  "정확한 근거를 빨리 찾는 층"이고, 종합은 기존 에이전트 체계(C-02 등)가 수행한다.
  이 분리가 NotebookLM류 도구의 환각 리스크를 구조적으로 피한다.
