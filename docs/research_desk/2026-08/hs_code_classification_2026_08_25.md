## 0. 먼저 바로잡는 두 가지 (기존 기록 정정)

1. **관세청 API는 10자리를 정식 지원한다** — 공식 기술문서의 `hsSgn` 항목크기 **10**,
   샘플값 `1001999090`(10자리), 우리 헬스체크도 `1507901010`으로 상시 통과 중.
   구 기록 A-043("6단위 필수")은 **무효** — 6자리도 동작하지만 10자리 제약은 없다.
   → 수작업이든 API든 10단위 수집에 기술 장애물 없음.
2. **A-028의 "1507901090·1507909000은 잘못된 코드" 판정은 오류** — 두 코드 모두
   실데이터 보유(각 8.23백만·3.93백만 kg 누적). MEMORY 정정 완료(A-196).

## 5. 폴더 구조 (본 커밋으로 생성)

대두유 모델(`{품목} ({HS6})/{용도} (.뒤4자리)/`)을 복제해 세분이 존재하는 품목에
세부코드 폴더를 신설했다. -0000 단일 품목(옥수수유·대두박·바이오디젤·1511.10·1514.11)은
기존 6단위 폴더가 곧 10단위이므로 README에만 명시. 각 폴더 README에 코드·근거·권장
국가·'실측 검증 대기'를 기재. 폴더명 정합: `Palm Oil (1511)`→`(1511.10)` 등 3건을
스크립트 표기와 통일(빈 템플릿 폴더 — A-075 자동 생성분이라 데이터 무손실).

## 6. 실측 검증 계획 (후속)

세번표 기준으로 만든 위 판정('무역 부재 예상' 포함)은 **API 프로빙으로 확정**한다 —
관세청 API가 10자리를 지원하므로(§0) Actions에서 코드별 1년 샘플 호출로 실존·무역
여부를 판정, 무역 부재 코드는 A-086 원칙(0 보존 vs 미보고 구분)으로 기록. 프로빙
잡은 별도 승인 후 추가(호출량 소량 — 코드 30여 개 × 1년).
