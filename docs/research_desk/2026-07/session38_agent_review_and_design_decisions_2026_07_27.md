## 1. C-04 ↔ P1-06 역할 중복 검토 (결론: **중복 아님 — 경계 명확화로 해결**)

| 구분 | C-04 Document Intelligence | P1-06 Semantic & Ontology |
|---|---|---|
| 본질 | **기계적 추출**(syntactic) | **의미 부여**(semantic) |
| 입력 | PDF·xlsx 원본 | C-04가 추출한 텍스트·표 |
| 처리 | 파싱·정규화·스키마 적재 | 엔티티 정규화·인과 온톨로지 구축 |
| 출력 | `data/raw/*.parquet` | `src/semantic/*.yaml` + 인과 엣지 |
| 판정 기준 | "무엇이 쓰여 있는가" | "그것이 무엇을 **의미**하고 가격에 **어떻게** 작용하는가" |

**중복 구간**: GAIN PDF의 **신호 태그 7종**(현 `ingest_gain_pdf.py`가 C-04 영역에서 수행 중).
→ **권고**: 태그 추출은 **C-04 유지**(기계적 키워드 매칭), 태그의 **의미·인과 매핑은 P1-06**.
   즉 C-04는 "수출규제 언급 있음"까지, P1-06은 "수출규제 → 공급위축 → SBO 가격상승" 엣지까지.

**C-04 추가 의견**: Mission B(인프라)는 P1-06과 접점 없음 → 중복 없음.

## 2. P1-05 ↔ P1-06 병합 검토 (결론: **병합 비권장 — 분리 유지 + 인터페이스 강화**)

| 관점 | 병합 찬성 | 병합 반대(우세) |
|---|---|---|
| 입력 | 동일 코퍼스(뉴스·PDF) 공유 | — |
| 산출물 | — | P1-05=**수치 신호**(−1~+1 감성), P1-06=**구조**(YAML·그래프). 산출 형식·검증 기준 상이 |
| 실패 모드 | — | 감성 오류(모델 캘리브레이션) vs 온톨로지 오류(논리·출처) — **디버깅 경로가 다름** |
| 모델 요구 | — | P1-05=분류(FinBERT·경량), P1-06=구조적 추론(thinking high) → **최적 모델 상이** |
| 컨텍스트 | 병합 시 1개 세션 | 분리 시 서브에이전트 격리로 **메인 컨텍스트 보호**(context engineering 원칙) |

**C-01 결론**: **분리 유지**. 대신 인터페이스를 명문화 —
`P1-05 감성값(metrics.yaml 정의 준수) → P1-06 엔티티에 속성으로 부착 → C-03`.
병합 시 "감성 모델 튜닝"과 "온톨로지 검증"이 한 에이전트에 섞여 품질 저하 위험이 큼.

> 단, **운영 부담**이 실제 문제로 확인되면(세션 수·토큰) 재검토 가능. 현재는 분리가 우세.
