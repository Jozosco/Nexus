## 4형식 재생성 방법 (2026-09-27)

발표 자료 2종·보고서(docx)·표(xlsx)는 `scripts/build_handover_docs.py`가 만듭니다. 내용을 고칠 때는
`05_PoC_범위_정의서.md`(보고서·표 정본)와 `scripts/handover_content.py`(발표 자료 내용 정본)를 고친 뒤 다시 실행합니다.

```
pip install python-pptx python-docx openpyxl     # 문서 산출 전용(파이프라인 코드 아님)
PYTHONPATH=. python scripts/build_handover_docs.py
```

- 글꼴: 제목 청정원고딕 B · 부제 청정원고딕 R · 본문 청정원명조 R(명조 대제목은 청정원명조 B). 글꼴 파일은 사내 전용이라 저장소에 넣지 않으며, 설치되지 않은 PC에서는 시스템 글꼴로 대체 표시됩니다.
- 양식: 컨설팅사 보고서 양식(백색 바탕·주황 강조·진회색 표 헤더·좌측 색 블록 목차)을 참고해 구성했고, 사진 자리는 단색 블록입니다.
- 빌더는 결정·작업 코드, '조정자' 표기, 실행 환경 상세가 발표 자료에 섞이면 생성을 멈춥니다(기밀·표기 규칙).

## 양식 안내

`01_작업정의서.md`는 현재 **임시 양식**(항목별 7칸)으로 작성되어 있습니다.
승인자의 공식 작업정의서 양식이 전달되면 **내용은 그대로 두고 형식만 그 양식에 맞춰 다시 정리**합니다.
해당 문서 첫머리에도 같은 안내가 적혀 있습니다.

## 확인하지 못한 사항 (정직 표기)

이 묶음을 쓰면서 **파일 존재를 확인하지 못했거나 시점상 확정할 수 없었던 것**은 다음과 같습니다.
읽는 사람이 오해하지 않도록 각 문서 본문에도 같은 표시를 해 두었습니다.

1. `reports/pipeline/latest/g1_daily_brief_latest.html` — 작성 시점(2026-09-09)에 **폴더가 아직 없습니다.**
   자동 실행 중에 생성·커밋되도록 설정되어 있으므로 다음 실행 후 생깁니다(설정은 확인함).
2. 자동 실행의 성공·실패 이력은 저장소 파일이 아니라 실행 화면에 있어, 이 문서에는
   기록 파일에 남은 판정만 옮겼습니다(예: 최근 실행에서 20개 작업 전부 성공).
3. 결정 대기 항목의 최신 상태는 대기열 문서가 기준입니다. 이 묶음에는 번호별 상세를 옮기지 않았습니다.
