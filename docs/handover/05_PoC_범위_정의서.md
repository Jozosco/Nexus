## 1. 목적과 배경 — 왜 PoC였는가

수입 대두유(콩기름) 조달은 세 가지 구조적 어려움이 겹쳐 있음.

| 어려움 | 내용 | PoC가 겨냥한 지점 |
|---|---|---|
| **리드타임 약 3개월** | 발주 → 선적 → 도착까지 약 3개월. 문제를 사후에 알게 됨 | 3개월 앞을 내다보는 준비·경보 |
| **높은 수입 의존** | 한국 식물성유지 공급의 82%가 수입(2022/23). 조대두유만 연 35만~40만 톤 | 원산지별 도착 단가 차이(중앙값 기준 약 200 $/톤)를 판단으로 잡을 근거 |
| **정보 비대칭** | 작황·환율·운임·정책·해협 상황을 실무자 한 사람이 매일 볼 수 없음 | 수백 개 지표를 시스템이 대신 감시하고 벗어난 것만 올림 |

**PoC의 성격**: 이 체계가 실제로 매일 돌아가고, 판단 근거로 쓸 만한 산출물을 내는지를 **실데이터로 증명**하는 것이 목적이었음.
두 가지 원칙은 처음부터 고정함.

- **판단 지원까지** — 시스템은 근거를 제시하고, 구매/보류 결정은 사람이 승인함. 발주·계약·결제에는 개입하지 않음.
- **검증 전 확률·전망 표현 금지** — 과거 유사 시기는 "과거에 이랬다"까지, 도착가 범위는 "참고 범위"로만 부름.

### 2.2 범위 밖(Out)

| # | 항목 | 이유·처리 |
|---|---|---|
| O-1 | **데이터 이관·회사 표준 데이터 플랫폼 통합 작업** | 해당 팀 소관. 본 PoC는 "이관 가능한 형태"(파일 기반 산출물·데이터 계약)까지만 갖춤 |

| O-3 | **구매 실행·자동 주문** | 사람 승인 원칙. 시스템은 근거 제시까지 |

## 4. 수집 → 처리 → 정제 → 검증 방법 (비전문가용)

```
① 모은다 → ② 검사한다 → ③ 시점을 맞춘다 → ④ 한 표로 합친다 → ⑤ 분석·발행·서명한다 → ⑥ 외부 교차검증
```

| 단계 | 하는 일 | 지키는 원칙 |
|---|---|---|
| ① 수집 | 매 영업일 새벽 외부 공개 데이터를 자동으로 받음. API로 못 받는 자료(관세청·보고서 PDF)는 사람이 올린 파일을 정해진 순서로 읽음 | **실패는 눈에 보이게 멈춘다** — 빠진 것이 있으면 조용히 넘기지 않음 |
| ② 품질 게이트 | 품질 점수(정확도·완전성·일관성·신선도·분포 가중 합산) → **통과(0.70 이상) / 주의(0.50~0.69) / 불합격(0.50 미만)**. 이어서 구조·이상치 검사, 자동 테스트 | **0과 빈칸은 다르다** — "교역 없음(0)"은 정보, "미보고(빈칸)"는 모름 |
| ③ 시점 정합 | 모든 숫자에 "언제부터 실제로 알 수 있었는가"를 붙임. 8월 수급 보고서는 8월 12일 발표이므로 8월 1일 분석에 쓰지 않음 | **발표 전 정보는 쓰지 않는다** · 수정치는 덮어쓰지 않고 회차별 보관 |
| ④ 통합 표 | 날짜 × 지표 격자표 한 장. 각 칸은 그날 기준 알 수 있었던 최근값 | **값이 둘이면 고르지 않고 멈춘다**(하드 실패) — 임의 선택은 그날그날 다른 답을 만듦 |

## 8. 후속 고도화 단계 구분 (PoC 이후)

### 8.1 2단계(G2) 재개 조건 — 네 가지 모두 충족 시 별도 승인으로 재개
1. **실시간 검증 창** — 60거래일 지평 첫 실측 대조는 가동 후 약 3개월, 계절 1주기와 비중복 표본 4건은 **2027년 이후**에야 확보됨. 그 전까지는 "과거 표본에서 재현한 범위"까지만 주장 가능
2. **추가 시장 데이터 3종** — 대두박·대두 정산가, 대두유 옵션 내재변동성(승인 완료·저장소 미반입) 수령 및 격자표 편입
3. **운영 실행 환경 확정** — 회사 표준 데이터 플랫폼에서의 배치 실행 표면 확정(해당 팀 소관)
4. **인수 측 해석 훈련** — 1단계 산출물(변인·경보·과거 유사 시기)을 읽는 훈련 완료

**2단계 시범판(Preview) 실현성 평가 요약(2026-09-14, `g2_preview_feasibility_2026_09_14.md`)**: 백테스트 전용 시범판은 기술적으로 지금 가능하나
확률 밴드 모델 코드는 아직 없다(최소판 1~3주 추정). 기준선(직전 250거래일 분포) 실측에서 명목 80% 범위가 실제 변동을 담은 비율은
**5/20/60거래일 78/74/62%**이고 2020·2025 같은 국면 전환기에는 22~27%까지 떨어진다 — 이것이 모델 없이 낼 수 있는 성적표의 전부다.
실시간 검증은 60거래일 첫 대조 2026-12-03, 통계적 의미는 2027-09 이후. **판정: 동결 유지**(위 4조건 무변경), 재개 시 기준선 산출물을 시범판 1판으로 사용.

## 9. 최소 운영 요건

### 9.1 일별 점검 (5분)
1. 자동화 실행 환경의 최근 3회 실행이 초록인가
2. 서명 기록 파일의 마지막 날짜가 **어제(영업일)** 인가
3. 최신 브리프를 열었을 때 "미수집"으로 빈 블록이 몇 개인가
4. 실패한 실행이 있다면 멈춘 지점이 **수집**인가 **게이트**인가 (수집이면 외부 기관 문제일 가능성이 큼)
5. 결정 대기열에 기한이 지난 항목이 있는가

### 9.2 실패 시 조치 순서
① 멈춘 지점 확인(수집 단계면 대기 후 수동 재실행) → ② 게이트 단계면 "데이터가 나쁜 것"인지 "파일이 안 온 것"인지 구분 → ③ "값 충돌"이면 지표 이름에 지역·국가 구분이 빠졌는지 의심 → ④ 조치 후 수동 재실행, 서명 기록에 한 줄 남는지 확인 → ⑤ 원인·조치를 결정·실패 원장에 기록

### 9.3 월 1회 점검
- 수동 업로드 계열 갱신(관세청 실적 · 수급 보고서 · 시세 이력 공백 · 거래소 거래량) — 빈 서식 파일 여부 포함
