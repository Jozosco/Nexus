# 기록 찾는 법 — "왜 이렇게 결정했나"를 되짚는 방법

> 이 프로젝트는 **모든 결정과 실패를 한 줄씩 남기는 방식**으로 운영됐습니다.
> 코드를 읽기 전에 이 기록을 먼저 보면, 같은 함정을 다시 밟지 않습니다.
> 작성 기준일 2026-09-09.

---

## 1. 어떤 기록이 어디에 있나

| 알고 싶은 것 | 파일 | 성격 |
|---|---|---|
| 과거에 무슨 문제가 있었고 어떻게 고쳤나 | `MEMORY.md` → `docs/memory_archive/YYYY-MM.md` | 시간순 원장(월별) |
| 지금 사람이 결정해 줘야 하는 것 | `docs/research_desk/decision_queue.md` | 대기열 |
| 만든 문서·코드가 외부 점검을 통과했나 | `docs/research_desk/cross_verify_log.md` | 판정 누적 |
| 어떤 순서로 무엇을 했나 | `git log` | 변경 이력 |
| 일정·진척·위험 | `reports/WBS_0907.xlsm` | 주간 현황 |
| 특정 주제의 상세 조사 | `docs/research_desk/YYYY-MM/*.md` | 조사·판정 문서 |
| 매일 무엇이 검사됐나 | `data/processed/signed_daily_stamps.csv` | 일별 서명 |

## 2. MEMORY 원장 읽는 법 (가장 중요)

### 2.1 구조

- `MEMORY.md` — 색인과 초기 실패 패턴만 유지(짧게 보존)
- `docs/memory_archive/2026-04.md` ~ `2026-09.md` — **월별 상세**. 실제 내용은 여기 있습니다

각 줄은 이렇게 생겼습니다.

```
| 날짜 | ID | 분류 | 문제 | 해결 |
| 2026-09-07 | A-246 | Bug | 지난주 실행 실패 분류 | ... 조치 내용 ... |
```

### 2.2 ID 앞글자 뜻

| 앞글자 | 뜻 | 이런 걸 찾을 때 |
|---|---|---|
| **A-** | 개별 작업(외부 API 문제·버그 수정·기능 추가) — 가장 많음 | "이 오류 전에도 있었나?" |
| **D-** | 데이터·구조에 관한 **결정** | "왜 사내 데이터를 안 쓰나?" (D-021) |
| **M-** | 분석 방법에 관한 결정 | "왜 이 분해 기법을 안 쓰나?" (M-010) |
| **R-** | 보고서·문서 산출 | "그 보고서 언제 뭐가 바뀌었나?" |
| **V-** | 검증·판정 결과 | "정식 가동 판정 근거는?" (V-004) |
| **C-** | 구조·관점(에이전트) 정의 | "이 분석 관점은 어떤 규칙을 따르나?" |
| **PM-** | 회차 요약 | "그 주에 전체적으로 뭘 했나?" |
| 그 밖에 | `L-`(라이브러리) `CI-`(자동 실행) `I-`(실행 환경) `S-`(초기 구축) `LLM-` `GEO-` `B-` | 좁은 주제 |

### 2.3 실전 찾기 3단계

```bash
# ① 키워드로 전 기간 검색 (예: 관세청)
grep -n "관세청" docs/memory_archive/*.md

# ② ID로 정확히 찾기 (예: D-021)
grep -rn "D-021" docs/ MEMORY.md

# ③ 최근 한 달만 훑기
head -40 docs/memory_archive/2026-09.md
```

> 팁: 문서 본문에 `(A-246)`처럼 괄호로 적힌 코드는 **원장으로 가는 링크**라고 생각하면 됩니다.
> 코드 자체를 외울 필요는 없습니다.

  업로드 보완, 열쇠 소유 주체 확인, 이관 관련 확인 등. 기한 감도가 "9월"인 것부터 처리합니다

## 4. 교차검증 원장

`docs/research_desk/cross_verify_log.md` (판정 전문은 `reports/cross_verify/`)

- 분석 코드·시장 보고서·용어 파일이 바뀌면 자동으로 외부 언어모델이 점검하고 판정을 남깁니다
- 표에서 볼 것: **상태**(무지적/지적) · **치명·높음 건수** · **요지**
- ⚠️ **"실패(미판정)" 줄은 그 대상이 검증되지 않았다는 뜻**입니다. 통과가 아닙니다
- 2026-09-07 기준 기록 185건 = 판정 126 · 미판정 59

## 5. git 기록 읽는 법

커밋 메시지는 앞머리로 종류를 구분합니다.

| 앞머리 | 뜻 | 예 |
|---|---|---|
| `feat:` | 기능 추가 | `feat: 관세청 업로드본 통합 파서` |
| `fix:` | 오류 수정 | `fix: 파이프라인 실패 분류 조치` |
| `data:` | 자동 실행이 남긴 데이터 | `data: E1 서명된 무소식 스탬프 append` |
| `docs:` | 문서 | `docs: GPT 교차검증 원장 갱신` |
| `refactor:` | 구조 정리 | — |

메시지 끝의 `[A-246]` 같은 대괄호는 원장 ID입니다.

```bash
git log --oneline -20                 # 최근 흐름
git log --oneline --grep="관세청"      # 주제별
git log --oneline -- src/reporting/    # 특정 폴더의 변경사
```

## 7. 한 가지 사실을 확인하고 싶을 때의 표준 경로

```
질문 예: "왜 사내 판매·재고 데이터를 안 쓰지?"

① grep -rn "내부 데이터" docs/memory_archive/ | head
② 나온 ID(D-021)를 다시 검색 → 결정 배경·사유 확인
③ 규칙 파일에서 실제 적용 지점 확인 → .claude/rules/modeling.md 상단
④ 필요하면 상세 조사 문서 → docs/research_desk/ 에서 해당 월 폴더
```

이 순서를 지키면 **"기록 → 결정 → 규칙 → 코드"** 로 내려가며 근거가 끊기지 않습니다.
