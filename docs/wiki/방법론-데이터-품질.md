# 방법론 — 데이터 품질·파이프라인

수집부터 리포트까지의 파이프라인 구조와 품질 게이트. 상세: `.claude/rules/data_pipeline.md`

## 파이프라인 구조 (일별 — 평일 KST 05:30)

```
외부 API 수집(커넥터 11종+) + 수동 업로드 파서
        ↓
C-08 DQSOps 게이트  ← 5차원 품질 점수·필수 산출물 존재 검증 (REJECTED = 차단)
        ↓
C-06 EDA 게이트     ← 구조 무결성·이상치·결측 검증
        ↓
Model Readiness     ← 목표변수·핵심 8변수·커버리지·as-of 충족 판정
        ↓
Feature Mart 빌드   ← DuckDB ASOF JOIN — 값충돌 시 하드 실패(자동 선택 금지)
        ↓
G1 분석·발행(3계층) + E1 서명 스탬프
```

체인 어디서 멈췄든 **E1 스탬프는 발행**됩니다 — 침묵이 아니라 "어디까지 검사됐는가"를
매일 기록.

  실시간 프록시(호르무즈·정책 뉴스 등) 일별 아카이브 · 전문 매체 RSS 6종
- **시맨틱 레이어**: 용어 152·인과 엣지 24+(검증된 것만 모델 해석에 사용, DAG 강제)

## 핵심 규율 (실패에서 배운 것)

1. **as-of 시점 정합** — 전 피처에 `available_at` 필수, 위반 시 모델 진입 차단(게이트)
2. **0과 결측의 구분** — "무역 없음(0)"은 정보, "미보고(결측)"와 혼동 금지
3. **키 유일성** — (지표·시점)당 1행: 지역·국가·계약 축은 지표 코드로 분리
4. **IQR 캡핑은 오류에만** — 2020·2022 같은 검증된 시장 충격은 캡핑하지 않음(꼬리
   위험 학습 보존)
5. **fail-closed** — 산출물 부재·검증 실패는 명시적으로 파이프라인을 멈춤. "조용한
   성공"은 금지
6. **모든 산출물 GPT 교차검증** — push 시 자동 발화, 판정은 원장에 누적
7. **원문 보존(S-5)** — 요약·판정의 근거 원문을 references/에 보관, 중복은 해시로 차단

## 피처 선택 5단계 게이트 (D-014)

품질(DQSOps PASS) → 단변량 스크리닝(|r|≥0.25·Granger) → 공선성 제거(VIF<5) →
ML 중요도(SHAP 3중 가중) → 실무자 검토 — 이 게이트를 통과한 변수만 모델 투입.
