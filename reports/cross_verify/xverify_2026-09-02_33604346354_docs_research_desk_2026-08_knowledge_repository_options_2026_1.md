### ① 수치·단위·논리 오류

- **[높음] 대상 문서 규모가 권장 구조와 일치하지 않음**
  - §1은 벡터 DB 판단 근거로 “문서 ~5천”을 제시하지만, §2의 실제 정규화 대상은 `2,175 + 300+ + 66 + 152 = 약 2,693건`이다.
  - 원문 PDF 2,175건까지 별도 문서로 더해야 약 4,868건이 되지만, 구조도에는 PDF 본문 적재가 포함되지 않는다. 따라서 약 5천 건이라는 규모를 아키텍처 판단에 사용하는 근거가 불명확하다.

- **[높음] EvidenceSpan 준수 주장과 출력 스키마가 모순됨**
  - EvidenceSpan은 `page + 원문 인용`을 강제한다고 했지만, 검색 출력은 “문서 경로·발췌·날짜·근거 등급”뿐이며 페이지와 원문 verbatim 인용 필드가 없다.
  - 검색 대상도 원문 PDF가 아니라 주로 요약 MD다. 요약문 발췌만으로 원문 페이지와 100% 일치를 보장할 수 없으므로 “준수만 하면 된다”는 결론은 성립하지 않는다.

- **[높음] FAISS·Chroma·LanceDB를 모두 ‘별도 인프라’로 분류한 것은 부정확함**
  - FAISS는 로컬 임베디드 라이브러리이며, Chroma와 LanceDB도 서버 없이 로컬/임베디드로 운영할 수 있다.
  - 승인 라이브러리 목록에 없다는 거버넌스상 배제 사유와, 별도 인프라라는 기술적 배제 사유를 혼동했다. 따라서 D-025 유형이라는 논리적 귀결은 입증되지 않는다.

- **[높음] Azure AI Search의 ‘Actions 종속’ 주장이 일반적으로 성립하지 않음**
  - Azure AI Search는 Portal·CLI·SDK·IaC 등으로도 구축할 수 있어 GitHub Actions에 본질적으로 종속되지 않는다.
  - 프로젝트 내부 배포정책 때문에 Actions가 필수라면 해당 정책과 연결 근거가 필요하다. 현재 문구만으로는 Phase 3 유보 근거가 과장돼 있다.

- **[높음] 생성 계층 분리가 환각 위험을 ‘구조적으로 피한다’는 결론은 성립하지 않음**
  - 에이전트가 검색 결과를 잘못 종합하거나, 근거에 없는 내용을 생성하거나, 잘못된 발췌를 선택할 위험은 그대로 남는다.
  - 인용 검증·답변-근거 정합성 검사·근거 부재 시 응답 거부가 구현되지 않은 상태에서 단순 계층 분리만으로 환각을 회피한다고 할 수 없다.

- **[참고] “비용 0”과 “잔존자산 100%”는 비용·승계 범위가 정의되지 않은 절대 수치임**
  - 로드맵 자체가 최소 하루의 개발 인력을 요구하므로 총비용은 0이 아니다. “신규 라이선스/인프라 증분비용 0”으로 한정해야 수치가 맞는다.
  - Parquet 파일은 이전할 수 있어도 CLI, Python 환경, TF-IDF 모델, 임베딩 모델 및 Snowflake 타입 호환성까지 자동 승계되는 것은 아니다. 따라서 잔존자산 100%도 측정 기준 없이 단정됐다.

- **[참고] “RAG의 절반이 이미 완성”이라는 비율에 산정 기준이 없음**
  - 단일 CSV 조인이 가능하다는 사실만으로 수집·정제·청킹·색인·검색·재랭킹·평가·인용 검증 중 정확히 50%가 완료됐다고 볼 수 없다. 분모와 완료 기준이 없는 수치다.

### ② 시계열 누수 위험

- **[치명] 단일 ‘날짜’만 있고 실제 이용 가능 시점(`available_at`)이 정의되지 않음**
  - 문서 작성일, 사건 발생일, 발행일, 저장소 유입일, 수정일을 구분하지 않는다.
  - 과거 시점의 예측·의사결정 재현에서 이후 작성된 research_desk 문서, MEMORY 결정, 정오표 또는 수정본이 검색되면 미래 정보가 그대로 유입된다. `available_at <= 예측 기준시점` 필터 없이는 백테스트가 무효화될 수 있다.

- **[높음] 전체 코퍼스로 TF-IDF를 학습하면 결과 필터링만 해도 누수가 남음**
  - 미래 문서를 검색 결과에서 제외하더라도, 그 문서가 IDF·어휘 사전 산정에 포함되면 과거 문서의 점수와 순위가 미래 코퍼스 구성에 의해 달라진다.
  - 과거 평가에서는 기준시점까지 이용 가능했던 문서만으로 vectorizer를 다시 적합하거나, 시점별 고정 인덱스를 사용해야 하지만 해당 규칙이 없다.

- **[높음] 태그·엔티티·감성·시맨틱 용어의 후행 보강에 대한 시점 통제가 없음**
  - 현재의 `signal_tag_mapping`, 152개 용어, 인과 엣지 및 엔티티가 과거 문서에 소급 적용되면 당시에는 존재하지 않았던 분류 지식을 이용해 검색하게 된다.
  - 추출 시점·모델 버전·ontology 유효기간이 없어 과거 검색 및 평가에서 누수 여부를 판별할 수 없다.
