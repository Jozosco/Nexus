## ④ 재현 불가능한 주장

| 심각도 | 지적 | 구체 근거 |
|---|---|---|
| **높음** | **자산 수량·크기와 “검색 코드 0건” 실측을 재현할 정보가 없다.** | 대상 git commit, 파일 glob, 제외 규칙, symlink·생성물 처리, 측정 명령, 결과 로그가 없다. `unstructured_index_*`도 정확한 파일명이나 스냅샷이 없어 2,175건·2,227행·6.5MB·0건을 독립적으로 다시 계산할 수 없다. |
| **높음** | **2,175개 요약의 원문 PDF 1:1 및 인덱스 조인 커버리지를 검증할 수 없다.** | 요약은 2,175건인데 인덱스는 2,227행으로 52행 차이가 난다. 중복, 미요약 원문, orphan row, 제외 문서의 내역과 조인 성공률이 없어 “원문↔요약이 한 테이블로 조인 가능”한 범위를 확인할 수 없다. |
| **높음** | **TF-IDF 검색 결과를 동일하게 재현할 설정이 없다.** | 문서/문단 단위, chunk 크기·overlap, 한국어 토큰화, stopword, n-gram, `min_df/max_df`, 정규화, 동의어 확장 순서, 중복 제거, tie-break, scikit-learn 버전이 모두 빠져 있다. 동일 parquet를 사용해도 상위 N 결과가 달라질 수 있다. |
| **높음** | **Phase 2 임베딩은 모델을 특정하지 않아 재현 불가능하다.** | `sentence-transformers`는 라이브러리명일 뿐이다. HF 모델 ID, revision/commit, 차원, pooling, normalization, truncation 길이, 배치 설정이 없다. HF의 최신 모델을 다시 받으면 같은 문서의 임베딩과 순위가 달라질 수 있다. |
| **높음** | **“이식성 100%·잔존자산 100%·Snowflake 승계”는 검증 자료가 없다.** | Blob은 parquet 파일을 그대로 보관할 수 있지만 Snowflake 적재 후 문자열·배열·임베딩 컬럼의 타입과 검색 동작까지 동일하다는 보장은 없다. 실제 적재 시험, schema mapping, 행 수·hash 대조, 검색 순위 회귀시험이 제시되지 않았다. |
| **참고** | **Phase별 ‘반나절’ 소요 추정은 재현 가능한 견적이 아니다.** | 대상 파일 수 외에 파서 예외 처리, PDF page 매핑, 테스트, 품질평가, CI·문서화 범위, 담당자 숙련도와 하드웨어 조건이 없다. 특히 EvidenceSpan 검증까지 포함하면 제시된 작업 범위와 반나절 추정이 맞는지 확인할 수 없다. |
