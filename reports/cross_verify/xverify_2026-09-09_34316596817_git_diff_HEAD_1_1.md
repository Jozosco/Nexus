### ① 수치·단위·논리 오류

- **[치명] 동일한 파일명을 가진 PDF 간 산출물·요약이 서로 뒤섞인다.**  
  출력 경로가 원본의 상대 경로가 아니라 `pdf.stem`만 사용한다(`markdown/{stem}.md`, `summaries/{stem}.md`). 서로 다른 하위 폴더의 `report.pdf` 두 개가 있으면 동일 경로를 공유한다. 특히 `--only-new` 필터는 변환 시작 전에 평가되므로 둘 다 통과한 뒤, 두 번째 PDF가 Markdown을 덮어쓰지만 요약은 첫 번째 것이 보존된다. 결과적으로 **본문은 두 번째 PDF, 요약의 원본 경로·해시·수치 후보는 첫 번째 PDF**가 되는 결정적 출처 오염이 발생한다.

- **[높음] 변경·삭제된 PDF가 산출물에 반영되지 않는다.**  
  워크플로는 항상 `--only-new`를 사용하고, 신규 여부를 `(MD_DIR / f"{p.stem}.md").exists()`만으로 판단한다. 기존 PDF 내용이 수정돼도 Markdown이 존재하면 변환을 건너뛰며, PDF가 삭제돼도 기존 Markdown·요약을 제거하지 않는다. 또한 Markdown만 있고 요약이 없는 경우에도 전체 PDF가 건너뛰어진다. 따라서 워크플로가 성공해도 분석 세션은 이전 버전 또는 삭제된 원본의 내용을 읽을 수 있다.

- **[높음] 일반 실행에서는 Markdown과 요약 메타데이터가 서로 다른 원본 버전을 가리킬 수 있다.**  
  `write_outputs()`는 먼저 `md.write_text(...)`로 Markdown을 갱신한 뒤, 기존 요약이 있고 `force=False`이면 즉시 반환한다. PDF가 바뀐 상태에서 기본 실행하면 Markdown은 새 내용이지만 요약의 SHA256, 분량, 표 수, 키워드 및 수치 후보는 이전 내용으로 남는다.

- **[높음] 일부 PDF 변환 실패를 성공으로 처리해 불완전한 산출물을 커밋한다.**  
  종료 조건이 `return 1 if fail and not ok else 0`이므로 성공이 한 건이라도 있으면 나머지 실패가 있어도 종료 코드가 0이다. 워크플로는 부분 산출물을 그대로 커밋·푸시하며, 실패한 PDF가 누락되었다는 사실을 CI 상태로 감지할 수 없다.

- **[높음] `--force`가 작성 완료된 수동 요약까지 미작성 골격으로 파괴한다.**  
  `force=True`이면 기존 요약의 상태를 확인하지 않고 `summ.write_text(...)`를 실행해 모든 세션 작성 내용을 `(미작성)`으로 초기화한다. 워크플로 입력 설명은 “요약 골격 덮어쓰기”지만 코드에는 골격과 작성 완료 요약을 구분하는 로직이 없다.

- **[높음] 보고되는 ‘표 개수’가 실제 문서의 표 개수가 아니다.**  
  `_tables_md()`는 기본적으로 60페이지만 처리하지만 요약에는 범위 표시 없이 `표 {len(r['tables'])}개`라고 기록한다. 61페이지 이후의 표는 집계에서 누락된다. 또한 표 추출 예외를 모두 잡아 빈 리스트로 반환하므로, 추출 실패도 “표 0개”로 기록되어 실제 무표 문서와 구분되지 않는다.

- **[높음] 수치 후보 정규식이 대두유 조달의 일반적인 가격·물량 표기를 체계적으로 누락한다.**  
  통화 기호가 숫자 뒤에 오는 `100$` 형태만 단위로 인식하므로 일반적인 `$0.45/lb`, `$1,200/MT`, `US$ 900/t`를 제대로 포착하지 못한다. 콤마 없는 네 자리 이상 수치(`1250 MT`)도 `\d{1,3}` 제한 때문에 누락된다. 대두유에 흔한 `¢/lb`, `cents/lb`, `$/lb`, `$/cwt`, `kg`, `lb`, `gal`, `bu` 등의 단위도 없다. 자동 요약의 수치 후보가 가격·물량 핵심값을 선택적으로 제외할 위험이 크다.

- **[높음] 키워드 적중 수가 단어가 아닌 부분 문자열 개수라 허위 적중을 만든다.**  
  `re.findall(re.escape(k), ..., re.IGNORECASE)`에 단어 경계가 없다. 예를 들어 `RIN`은 `during` 안의 `rin`에도 적중한다. 따라서 `RIN(n)` 같은 규제·바이오연료 관련성 지표가 실제 언급 횟수보다 크게 부풀려질 수 있다.

- **[높음] 스캔 PDF를 처리할 수 없는데도 성공 산출물로 취급하는 논리적 모순이 있다.**  
  OCR 단계가 없고 스캔 의심 문서도 실패 처리하지 않는다. 출력에는 “이미지 판독 필요”라고 쓰는 반면 요약 골격에는 “원본 PDF는 직접 판독하지 않음”이라고 명시한다. 따라서 해당 정책을 따르면 스캔 문서의 핵심 주장·수치 검증은 수행할 방법이 없지만 워크플로는 정상 성공으로 커밋한다.

- **[참고] 표 셀의 `|`를 이스케이프하지 않아 수치와 단위 열이 어긋날 수 있다.**  
  셀은 줄바꿈만 치환한 뒤 그대로 `|`로 결합한다. 원문 셀에 파이프 문자가 있으면 Markdown 열이 추가되어 가격과 단위 또는 기간 헤더의 대응이 깨진다.

- **[참고] 대문자 확장자 PDF는 자동 처리되지 않는다.**  
  워크플로 경로 필터와 `rglob("*.pdf")`가 모두 소문자 `.pdf`만 대상으로 한다. Linux 러너에서는 `.PDF` 파일이 트리거·검색 모두에서 누락된다.

### ④ 재현 불가능한 주장

- **[높음] “판독 재현성” 주장을 뒷받침할 실행 환경이 고정되어 있지 않다.**  
  `pip install pymupdf pdfplumber`에 버전 또는 해시 고정이 없고, `ubuntu-latest`, `actions/checkout@v4`, `actions/setup-python@v5`도 가변 참조다. 산출물에는 실제 PyMuPDF·pdfplumber 버전이나 변환기 커밋도 기록하지 않는다. 라이브러리 버전에 따라 텍스트 순서·표 추출·폰트 정보가 달라질 수 있어 동일 PDF로 동일 Markdown을 재생성할 수 있다는 보장이 없다. `date.today()`도 산출물에 포함되어 동일 입력의 바이트 단위 재현을 방해한다.
